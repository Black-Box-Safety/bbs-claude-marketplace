## Rulings (decided)

- **Quality bar, not token bar.** Skills go in if genuinely good and plausibly valuable to a
  rep. Token cost is a tiebreaker, never the reason to exclude.
- **`bbs-commons`** is the name for curated, generally applicable, third-party skills and
  plugins. Nothing BBS-specific ever lives there; that belongs in `bbs-sales` /
  `bbs-foundations`. Two channels: real upstream plugins → pinned external entries in
  `marketplace.json` (like `impeccable` today); bare skill dirs → vendored under
  `plugins/bbs-commons/skills/` with `SOURCES.md` (upstream URL + commit SHA per skill).
- **Full browser access for reps.** No deny rules and no doctrine lines restricting browser
  use. Reps need it to find products online. `superpowers-chrome` (drives the rep's real
  Chrome, logged-in sessions) is the pick; add its browser tool to managed
  `permissions.allow` so every action runs without a prompt. Existing pricing-source rule
  (no price from the open web) is unchanged and is not a browsing restriction.
- **Caveman** goes in commons (source `JuliusBrussee/caveman`, unversioned marketplace; pin
  by ref). Task 11 ADMIN-CLEANUP text must be adjusted: keep, sourced via the bbs
  marketplace; the statusline-removal note stands.
- **Humanizer is redundant** for rep email: `bbs-voice-template` already vendors the 35
  AI-writing patterns from blader/humanizer and every `<first>-voice` skill strips them
  first. Not in commons. Add "refresh `ai-patterns.md` from upstream" to quarterly hygiene.
- **Superpowers stays Parker's.** Developer-oriented; its session-start hook injects a large
  mandatory block. Vendor only `brainstorming` and `writing-plans` (MIT) into commons if
  wanted.
- **`claude-persona`** (synthetic buyer panels) is admin/marketing tier, not a rep default.
  Each persona is a separate `claude -p` subprocess; burns base-plan limits. Seed personas
  from SCPRS buyer segments, run on Haiku, enable for Parker only.
- **Draft-first deny list scope** stays email + e-sign. `outlook_create_event` (attendee
  invites go out automatically), `outlook_respond_to_event`, and Teams send tools are
  outbound but deliberately not denied. Ruling recorded so it reads as a decision, not an
  oversight.

## Supplier discovery for unknown items (researched, live-fired)

**Primary: Firecrawl `firecrawl_agent`, schema-constrained**, wrapped as a `supplier-scout`
subagent in `bbs-sales`. **Fallback:** built-in `WebSearch` + `WebFetch` subagent with the
same output contract. Live test: fed a wrong premise ("Allegro 9401-06 ventilation blower"),
the agent returned empty suppliers, the correction (9401 = manhole lid lifters; blowers are
95xx), two cited equivalents, zero credits. `WebSearch` on the same string returned Amazon
and Walmart. `firecrawl_search` price snippets were shopping-widget garbage — the
hallucination vector.

Integration, three changes:
1. Connector access: move Firecrawl from "Parker/Griffin only" to everyone who quotes, in
   claude.ai connectors, after the key rotation (ADMIN-CLEANUP). Not as a managed MCP entry
   (static header on every workstation).
2. New `plugins/bbs-sales/agents/supplier-scout.md`. Tools: Firecrawl agent/status/search/
   scrape, WebSearch, WebFetch, SCPRS `market_product_search`, `bc_find_item`. No Write.
   Output: manufacturer, authorized distributors, alternates, MOQ, lead time, published
   price **with URL + observed date or null**, contact path.
3. `bbs-sourcing` Step 5c ("search online") → dispatch `supplier-scout`. Order: SCPRS → BC →
   `bbs-suppliers` brief → Firecrawl. Move `bbs-sourcing` from `bbs-website` into
   `bbs-sales` in the same commit; create or trim its four missing `references/` files.

Pitfalls: free tier is 5 agent runs/day org-wide, then dynamic pricing — set `maxCredits`
on every call; deep run is async (~7 min), kick off and poll; whether subagent tokens count
against the rep's 5-hour window is unverified.

## Structural proposals (not yet framed as tasks)

1. **Plan tier: confirmed Team (2026-09-13).** Managed settings, deny rails, analytics, plugin
   auto-enable all reach every seat. Reps may install basic packages and extensions as
   needed. No individual-Pro gap to work around.
2. **Headless runner for heavy work.** One always-on `claude -p` runner (API-billed or a
   Team seat) watches the quotes mailbox, files the RFQ, extracts line items to `rfq.json`,
   runs precedent + SCPRS + Grainger lookups, posts a pre-brief to Teams. Reps start at 60%
   done; their 5-hour windows stay for judgment. Replaces the Power Automate "dumb filer".
3. **Precedent index.** Nightly DuckDB over every `quote-log.md`, `FILLED/` metadata, and a
   BC quote export. One skill, one query, near-zero tokens. Feeds win-rate by lane.
4. **Win/loss backfill from SCPRS.** Match BBS bids to SCPRS awards by agency/item/date.
   Lost bids become outbound plays (who won, price gap, reorder window).
5. **Pricing provenance as a check** (hook 4) rather than a doctrine sentence.
6. **Form-fill verification script** (hook 5).
7. **Deadline sweep** (hook 9) replaces the parked Supabase cockpit.
8. **Sourcing must capture**: every `supplier-scout` result written to `bbs-suppliers`
   automatically. The flywheel only works if capture is automatic.
9. **FLAGS digest**: weekly headless pass over all `FLAGS.md`, summary to Teams.
