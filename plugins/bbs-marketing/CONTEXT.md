# Which skill

Layer 1. Match the request, then read that skill. One skill per turn unless the rep
already finished the previous stage and asked to continue.

| The rep wants | Skill | Stop |
|---|---|---|
| A new piece, and no program folder exists | `marketing-intake` | The brief is on disk |
| A one-pager, leave-behind, sell sheet, punchout card, or line card, and the brief exists | `sales-one-pager` | Copy is drafted, then a render only after the rep leaves the copy file in place |
| An outbound email about a piece or a campaign | `campaign-email` | One draft. A person sends it |
| A logo on a piece | `marketing-assets` | A rights decision from `references/ASSETS.md` |
| What we already made: a brochure, capability statement, line card, or pitch deck | `deck-precedent` | A pointer to the file on the marketing desk |
| A Grainger hot list, promo page, or campaign landing page | `grainger-promo-page` in `bbs-sales` | That skill's own stop. It is not this plugin |
| Federal or prime slide copy | `bbs-deck-voice` in `bbs-foundations` | That skill's own stop |

Piece type and track are different. The program folder owns the account. The track owns
dress and argument. Read `references/tracks/ROUTING.md` inside `marketing-intake`, not here.

A promo page and a one-pager both end up in front of a buyer. They stay separate skills.
One is a print piece from approved claims. The other is a priced hot list.
